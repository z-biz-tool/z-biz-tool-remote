**隔离夹具原则（P1–P7，所有测试必须遵守）**：

- **P1 不碰真实设备**：绝不以开发者本机作为被控端跑注入测试。所有 `simulate_input` 相关测试**只测 Rust 侧的校验与拒绝逻辑**（坐标越界、速率、黑名单、`origin=automation`、`inputPaused`），**不实际调用 enigo 产生真实键鼠事件**——通过注入 trait/mock 边界实现。
- **P2 不碰真实屏幕**：截屏测试用**预置的固定测试图**（合成图像）作为 `xcap` 的替身输入，保证脏区算法、tile 编码、JPEG 体积统计可重复。
- **P3 服务端隔离**：每个测试用 `mkdtempSync` 建独立数据目录 + 随机端口（沿用现有做法），测试间零共享状态。
- **P4 网络隔离**：所有 WS/HTTP 测试连 `127.0.0.1` 随机端口；**禁止**任何测试连接 `101.37.80.51` 或其它公网地址；性能测试的网络劣化用本地代理（`toxiproxy` 类）模拟，不用真实公网。
- **P5 凭证隔离**：测试账号用一次性生成的随机用户名/口令；测试结束清理；**禁止**在测试代码或快照中出现任何真实 token。
- **P6 时间可控**：涉及超时/宽限期/退避的测试注入可控时钟（fake timer），不靠 `sleep` 等真实时间（避免慢与不稳定）。
- **P7 平台条件跳过**：平台特有测试（macOS 权限、Windows 凭据库）用条件跳过并**显式报告为 skipped**，不得静默通过。

## 4. 测试矩阵

### 4.1 单元（~240 例，节选关键项）

帧头编解码（`protocol.rs`，S3）：24B 定长往返一致、`hasExt` 时 28B、`payloadLen=0xFFFF` 边界、非法 magic/version 一律拒收｜脏区判定（`capture_diff.rs`，S3）：全静止→0 dirty、单 tile 变化→1 dirty、49%→分块、51%→退回全帧、第 30 帧强制 keyframe｜退避计算（`signaling.ts`，S1）：序列 1,2,4,8,16,30,30…、jitter 在 ±20% 内、第 10 次后停止｜自适应决策（`adaptive.ts`，S3）：各 RTT/丢帧组合映射到正确档位、升档需连续 2 周期、降档立即、自定义档不自动调整｜坐标归一化与边界（`input.rs`，S1）：`[0,1]` 内通过，`-0.01`/`1.01`/`NaN` 一律拒收，多屏分辨率下映射正确｜按键黑名单（`input.rs`，S1）：黑名单组合拦下、开启「允许系统级快捷键」后放行、`key-type` 控制字符与 >4KB 均拦下｜`origin` 校验（`input.rs`，S1）：`source="automation"` **一律 Err**、`"human"` 通过、缺失 `origin` 视为 automation（fail-closed）｜路径消毒（文件传输，S2）：`../`、绝对路径、`\0`、Unicode 双向覆写字符全部剥离｜token 散列比对（`storage.js`，S1）：正确通过、错误拦下、比对为常量时间｜权限判定矩阵（`server.js`，S1）：`view-only` 不允许输入、`input` 不允许文件、`full` 全通、非成员全拦｜`toWsUrl`（`storage.ts`，S1）：公网域名→`wss://`、`localhost`/`127.0.0.1`/`.local`→允许 `ws://`、非法输入→空串。

### 4.2 集成（~95 例，节选）

服务端鉴权与状态机：成员表增删改查、`assertSessionMember` 各角色/权限组合、`FORBIDDEN` 路径、宽限期进入与超时、`RESUME_SESSION` 成功与 `resumeToken` 不匹配、`KICK_CLIENT` 仅 host 可用、`LEAVE_SESSION` 精准移除单个成员、`maxPayload` 超限断连、`bufferedAmount` 背压丢屏幕帧但不丢信令、per-message 异常隔离、优雅关闭广播 `SERVER_SHUTDOWN`、`/healthz` 与 `/readyz`、速率限制触发与解锁、设备归属冲突 `DEVICE_CONFLICT`、配对码 TTL 与 5 次失败作废、SAS 双方一致性与未确认不建会话、存储层 JSON→SQLite 迁移计数一致。

### 4.3 端到端（~20 例）

双 WS 客户端模拟双端（沿用 `makeClient`），覆盖：注册登录→我的设备→配对码→SAS 核对→授权（三档位各一）→建会话→首帧到达（PERF-14）→鼠标与键盘注入→切显示器→文件传输（含 sha256 校验与危险扩展名拦截）→聊天→暂停输入→降级权限→踢出→优雅退出→被控端主动断开→重连恢复（PERF-15）→宽限超时会话关闭→版本协商失败提示→容量超限提示。**全部走 `127.0.0.1`，不驱动真实 GUI，不产生真实键鼠事件。**

### 4.4 故障注入（~16 例）

网络瞬断 5s（宽限内）→ 自动 `RESUME_SESSION`，恢复 ≤3s，授权不丢失｜网络断开 45s（超宽限）→ 收 `SESSION_CLOSED`，UI 显式回落到 `main`，**不得**停留在 controlling｜服务端进程重启 → 200 模拟客户端在 ≤60s 内全部重连（退避+抖动生效），服务端不 OOM｜RTT 阶跃 40→400ms → ≤6s 内降档，无卡死｜丢包 20% → 降档 + keyframe 恢复 ≤500ms，无累积画面漂移｜慢消费者（控制端不读）→ 服务端按 `bufferedAmount` 丢屏幕帧，信令与输入不丢，内存有界｜超大消息（>maxPayload）→ 连接被断、服务端不崩、写审计｜`data.json` 损坏 → 服务端回退空态并可启动（不静默丢用户数据，需告警）｜`state.json` 损坏 → 客户端回退空态（**已有能力，需回归保护**）｜TCP 半开连接 → 30s 协议层 ping 超时后 `terminate()` 回收｜TLS 证书 pin 不匹配 → **硬失败**，UI 无「忽略」按钮，写审计｜证书过期 → 连接失败并给出可操作提示｜时钟偏移 ±10min → 不影响安全决策（`captureTsMs`/`ts` 仅用于统计与 nonce）｜存储写满 → `/readyz` 失败，拒收新会话而非崩溃｜单条消息处理抛异常 → 其它连接不受影响｜被控端进程被杀 → 服务端宽限后关闭会话并通知控制端。

### 4.5 安全（~45 例）

**逐条覆盖 SEC-01…SEC-25**（[04](./04_数据安全与可靠性.md) §14），并额外包含对抗性用例：用 B 的 token 对 A 的设备发 `INPUT_EVENT`／发 `SCREEN_FRAME`／发 `FILE_OFFER`／发 `CHAT_MESSAGE`（四者均须拒 + 审计 + 被控端告警）｜重放已失效的 `sessionToken`／`resumeToken`｜跨会话挪用密文帧（AEAD 绑定 `sessionId` 校验）｜nonce 重复｜`GET_ONLINE_DEVICES` 尝试获取跨账号设备｜伪造 `sameUser=true` 字段（必须由服务端计算，客户端传值无效）｜远端消息尝试写入 `trusted` 列表｜`origin.source="automation"` 经各种路径调用 `simulate_input`（JS 直接 invoke、被篡改的 store、伪造事件）｜CSP 违规注入（聊天/文件名含 `<script>`）｜路径穿越文件名｜`view-only` 下发输入事件｜`inputPaused` 时绕过 JS 直接 invoke｜生产无 TLS 启动｜明文 `ws://` 连公网地址｜CORS 非白名单 Origin｜token 出现在 URL/日志/历史记录/审计的**全量扫描断言**｜`capabilities` 与 CSP 配置的静态快照测试（防止回归）。

### 4.6 性能与兼容

性能：PERF-01…PERF-24 各一条基准脚本，产出 JSON 报告与趋势对比；**不进 CI 阻断**，仅 nightly 记录（波动大）。E0 基线必须在 S3 改造**之前**先测一次，否则 PERF-05/06/07 的相对收益无法计算。
兼容：三平台（macOS arm64+x64 / Windows x64 / Ubuntu x64）× {构建产物可生成、首次启动、持久化路径正确、权限申请流程、系统通知可见、按键映射正确、文件对话框可用、托盘指示可见} = 12 组；平台特有用例按 P7 条件跳过并显式报告。

**安全风险（S）**：RISK-S1 越权注入链未完全堵住（缓解：成员表 + 双侧校验 + 45 条安全用例）｜S2 假加密残留误导用户（缓解：彻底删除字段而非补实现，并加静态断言禁止再引入）｜S3 强制 TLS 导致自托管用户部署失败而**私自关掉校验**（缓解：提供 Caddy 自动签发示例；UI 上根本不提供「忽略证书」选项）｜S4 E2EE 密钥泄露（缓解：密钥不出 Rust、不落盘、无读取 command）｜S5 提示注入操纵 Agent（缓解：G-08 + Agent 无副作用能力）｜S6 审计日志含敏感内容（缓解：K-08 + CI 脱敏断言）｜S7 速率限制误伤 NAT 后多用户（缓解：IP+账号双维度 + 白名单）｜S8 refresh token 改散列后老用户被迫重登（缓解：提前公告）｜S9 文件传输成为恶意软件投递通道（缓解：扩展名黑名单 + L2 确认 + 接收方选路径 + 不自动落盘）｜S10 信任列表被本地篡改（缓解：加签或存密钥库 + 过期）｜S11 多会话导致被控端注意力分散而漏看指示（缓解：并发上限 2 + 每会话独立浮条）｜S12 CSP 收紧破坏 antd 内联样式（缓解：保留 `style-src 'unsafe-inline'` 并逐步替换）｜S13 局域网直连路径绕过服务端管控（缓解：仍 TLS + 仍授权 + 服务端保留记录）｜S14 旧版本客户端连新服务端造成安全降级（缓解：`HELLO` 协商拒绝低于最低版本的客户端）。

**工程风险（E）**：RISK-E1 S3-03 Rust 推流技术栈新（先 1pd spike）｜E2 tokio 引入增大二进制与编译时间｜E3 SQLite 原生依赖使 Docker 构建复杂化（用预编译二进制）｜E4 client/server 必须同版本发布（`HELLO` 协商 + 明确提示）｜E5 `_shared/` 孤儿组件可能与 antd 6/React 19 不兼容（挂载前先编译验证）｜E6 键盘输入跨平台/跨输入法差异大（用 `e.code` + 平台映射表 + 三平台 QA）｜E7 脏区算法误判导致画面残留（keyframe 兜底 + PERF-19 指标）｜**E8 「改测试让它通过」的诱惑**（CT-12 不可豁免 + 代码评审检查断言 diff）｜E9 性能测试环境不一致导致数据不可比（固定基准机 + 记录环境元数据）｜E10 长稳测试耗时（nightly 而非 PR）｜E11 三平台 CI 时长与成本上升（矩阵并行 + 缓存）｜E12 迁移脚本失败导致数据丢失（迁移前自动备份 + 计数校验 + 可回滚）｜E13 工期估算偏乐观（S4 预留 20% buffer）｜**E14 误删 `_shared/`**（已在 [03](./03_技术架构与性能优化.md) §10 明确标注「保留并挂载使用」）｜E15 `release.sh` 改动影响既有发版流程（先在分支演练）。

**产品风险（P）**：RISK-P1 授权弹窗过频导致用户习惯性点「允许」（缓解：展示 SAS 与账号信息、默认焦点不在确认键、L2 文案具体化）｜P2 被控指示过于侵入影响正常使用（缓解：可折叠但**不可完全隐藏**，V-11）｜P3 自适应降档造成画质突变用户困惑（缓解：降档时提示原因 + 手动覆盖入口）｜P4 语义预设替代数字滑块后高级用户不满（缓解：保留「自定义」展开）｜P5 移除 `en-US` 选项被视为功能退步（缓解：优先补字典，仅在资源不足时移除）｜P6 强制同版本发布影响已部署用户（缓解：发布公告 + 服务端对旧版给出升级指引而非静默失败）。
