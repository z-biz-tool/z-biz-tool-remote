# 生产收口记录：8080 公网暴露 → WSS 反代（2026-10-25）

> 本文记录 remote 信令服务在生产机 `101.37.80.51` 上真实发生的架构变更与验证证据。
> 与 `2026-10-21-暴露面修复-部署runbook.md` 配套：runbook 讲"代码层修了什么"，本文讲"生产机怎么落的地"。

## 1. 背景：修复一直没真正上线

2026-10-21 的修复提交 `8cc68c7` 修了三个暴露面（注册免鉴权 / 无 TLS / 令牌进 URL），但 10-25 上机核验发现：

| 维度 | 设想 | 生产实际 |
|---|---|---|
| 仓库 | monorepo `z-biz-tool-remote/z-biz-tool-remote-server/` | 独立仓 `z-biz/z-biz-tool-remote-server`（`origin` 指向它） |
| 布局 | `server.js` 在仓库根 | `server.js` 在 `src/` 下 |
| 版本 | 含 `8cc68c7` | HEAD `472249b`，停在 2026-09-05 旧版 |
| 实锤 | — | `src/server.js:123` 仍是 `url.searchParams.get("token")` |

也就是说：**修复被提交到了一个和生产没有关系的代码树**。"修复没部署"的真实原因是"部署的是另一个仓"。

## 2. 移植与上线（2026-10-25）

### 2.1 代码移植

把 `8cc68c7` 的修复按生产 `src/` 布局移植进生产仓，提交：

```
427da77 fix(security): 移植 8cc68c7 安全修复到生产 src/ 布局
```

移植内容：`WS_TOKEN_TRANSPORT`（令牌不再默认走 URL）、注册限流 + 邀请码、`controlGrants`（控制权授予）、在线设备按租户裁剪、TLS 启动校验。

**`data.json` 全程未动**（生产运行数据：用户/设备/会话），部署前后均为 `users=3 devices=2`。

### 2.2 从"裸端口"改为 WSS 反代

生产原本是 `node src/server.js` 裸监听 `0.0.0.0:8080`，明文 HTTP/WS，防火墙 `ufw inactive` + `iptables INPUT ACCEPT` —— 8080 对全公网敞开。

现改为两层：

```
客户端 ──wss://remote.zopc.top:443──> nginx（通配符证书 *.zopc.top）
                                        └──proxy_pass──> 127.0.0.1:8080（node）
```

- nginx 配置：`/etc/nginx/conf.d/remote-ws.conf`（`server_name remote.zopc.top`，`Upgrade/Connection` 升级头，`proxy_read_timeout 3600s`）
- 复用现有 Let's Encrypt 通配符证书 `/etc/letsencrypt/live/zopc.top/`（SAN 含 `*.zopc.top`），**无需新签证书**
- node 启动加 `HOST=127.0.0.1`，服务不再监听公网

### 2.3 验证证据（外网实测）

| 检查项 | 结果 |
|---|---|
| `GET https://remote.zopc.top/health` | `200` `{"ok":true,...}` |
| `101.37.80.51:8080` 外网直连 | `ECONNREFUSED`（已关闭） |
| `101.37.80.51:443` | OPEN（nginx） |
| 服务监听地址 | `127.0.0.1:8080`（pid 2489223） |
| 启动日志 `tokenTransport` | `frame`（最严模式） |
| 数据完好性 | `users=3 devices=2`（与部署前一致） |

> 注：本机 `curl` 为 LibreSSL，对 `zopc.top` 主站也返回 000（exit 35），属客户端工具缺陷；用 Node `https` 实测 200，服务端正常。

## 3. 对客户端的破坏性变更（必须同步）

**公网 `ws://101.37.80.51:8080` 已不可用。** 所有已安装客户端必须把服务端地址改为：

```
wss://remote.zopc.top
```

客户端 `signaling.ts` 默认 `tokenTransport = "frame"`，与该服务端模式匹配，无需改代码。

## 4. 回滚

```bash
# 代码回滚
cd ~/z-biz-tool-remote-server && git reset --hard 472249b

# 网络回滚（恢复公网 8080 + 去掉 nginx 入口）
sudo rm -f /etc/nginx/conf.d/remote-ws.conf && sudo nginx -t && sudo systemctl reload nginx
# 重启时去掉 HOST=127.0.0.1：
setsid nohup node src/server.js >> server.log 2>&1 < /dev/null &
```

备份点：`/tmp/remote-backup-<timestamp>/`（含 `server.js`、`data.json`、`nginx/conf.d` 快照）。

## 5. 仍待处理

1. **服务无守护**：当前是 `setsid nohup` 直跑，机器重启不会自启。建议写 systemd unit（`Restart=always`）。
2. **阿里云安全组**：8080 规则仍在（主机侧已无监听，实际不可达，但建议在控制台删掉该入站规则）。
3. **`src/storage.js` 未纳入 git**（`?? src/storage.js`）：它是账号系统的持久化实现，应补提交，否则重建工作区会丢。
4. **`src/server.js.bak`** 是手工改动残留，确认无用后删除。
5. `WS_TOKEN_TRANSPORT=frame` 下，任何仍走 `?token=` 的老客户端会连接失败 —— 这属于预期行为（暴露面已关闭）。
