| # | 暴露面 | 修复口径 | 环境变量 |

## 1. 证书（certbot）与挂载

```bash
# 没有证书先签（域名要已解析到 101.37.80.51，80 端口临时放行）：
certbot certonly --standalone -d remote.<你的域名>
# 已有证书则确认路径：
ls -l /etc/letsencrypt/live/remote.<你的域名>/
#   privkey.pem / fullchain.pem / cert.pem / chain.pem
```

**挂载口径（关键细节）**：`live/` 里的文件是指向 `../../archive/…` 的符号链接，
只挂 `live` 目录进容器，链接目标在容器里不存在 ⇒ 启动报「TLS 文件不存在」。
所以**挂整个 `/etc/letsencrypt`**：

```bash
# .env 里：
TLS_CERT_DIR=/etc/letsencrypt
TLS_KEY_PATH=/certs/live/remote.<你的域名>/privkey.pem
TLS_CERT_PATH=/certs/live/remote.<你的域名>/fullchain.pem
```

compose 已默认把 `${TLS_CERT_DIR:-./certs}` 以只读挂到容器 `/certs`。
**续期后必须重启容器**（Node 只在启动时读一次证书材料），加 deploy-hook：

```bash
certbot renew --deploy-hook "cd $REPO/z-biz-tool-remote-server && docker compose restart signaling"
```

备选（不想挂 `/etc/letsencrypt`）：deploy-hook 里 `cp` 到 `$REPO/z-biz-tool-remote-server/certs/`，
`TLS_CERT_DIR` 留空（默认 `./certs`）。

## 2. 环境变量清单（.env）

```bash
# —— 鉴权 ——
AUTH_TOKEN=<openssl rand -hex 32>     # compose 要求必填；账号模式+共享令牌双模式

# —— 注册闸门（修复 1）——
INVITE_CODE=<openssl rand -hex 16>    # 生成后只发给团队；**不设=注册对所有 IP 敞口**
REGISTER_RATE_LIMIT=5                 # 每 IP 每窗口注册尝试次数（0=关闭，别关）
REGISTER_RATE_WINDOW_MS=600000        # 10 分钟

# —— TLS（修复 2）——
TLS_CERT_DIR=/etc/letsencrypt
TLS_KEY_PATH=/certs/live/<域名>/privkey.pem
TLS_CERT_PATH=/certs/live/<域名>/fullchain.pem

# —— 令牌传输（修复 3）—— 灰度第一步：both
WS_TOKEN_TRANSPORT=both
WS_AUTH_TIMEOUT_MS=5000

# —— 发布面 ——
HTTPS_PORT=443                        # 容器内始终 8080；发布到 443，安全组随之收口
BIND_ADDR=0.0.0.0                     # 前面有反代时才改 127.0.0.1；本例直发，靠安全组收口
```

> `BIND_ADDR` 默认 `0.0.0.0`（compose 的 `${BIND_ADDR:-0.0.0.0}`）——**默认即公网可达**，
> 本例的安全模型是「HTTPS_PORT=443 + 安全组只放 443」，不要依赖 BIND_ADDR 兜底。

## 3. 部署命令

```bash
cd $REPO/z-biz-tool-remote-server
docker compose build
docker compose up -d
docker compose ps                     # STATUS 应为 healthy（healthcheck.js 自动尝试 https→http）
docker compose logs --tail=50 signaling | grep -E '"tls"|tokenTransport'
# 期望： "tls":"enabled" 与 "tokenTransport":"both"
```

顺序要点：**先放行 443、部署并验证通过，再收口 8080**（见第 5 步），
不要先把 8080 关了导致新旧实例切换期间服务空窗。

## 4. 灰度顺序（引用 8cc68c7 提交里的口径，勿调换）

服务端与客户端**必须同版本发布**，顺序：

1. **服务端先上 `WS_TOKEN_TRANSPORT=both`**（本 runbook 第 2 步即此状态）：新老客户端都收；
2. **客户端发新版**（默认 `frame`，URL 里不再出现令牌）；
3. 观察至少一个完整使用周期后，**服务端切 `WS_TOKEN_TRANSPORT=frame`**（改 .env 后
   `docker compose up -d` 重建）：查询串彻底不再被读取。

`both` 是**灰度态不是稳态**：此模式下服务端仍读 `?token=`，令牌会进浏览器历史 /
反代 access_log / 截图。客户端铺完应立即切 `frame`。

## 5. 安全组收口（阿里云控制台 / API）

| 方向 | 端口 | 动作 |
|------|------|------|
| 入 | 8080/tcp | **删除**（旧暴露面；灰度验证通过后才删） |
| 入 | 443/tcp | 保留（0.0.0.0/0 或办公网段；需要客户端跨网就连公网） |
| 入 | 22/tcp | 收紧到办公网 IP |

验证收口（外网机器）：

```bash
curl -m 5 http://101.37.80.51:8080/healthz     # 预期：超时/拒绝
curl -m 5 https://101.37.80.51/healthz         # 预期：{"ok":true,...}
```

## 6. 用 security-probe.mjs 验证（验收口径）

任一带 Node≥18 的机器（零依赖，不用 npm install）：

```bash
PROBE_BASE_URL=https://101.37.80.51 node scripts/security-probe.mjs
# 或显式传参：node scripts/security-probe.mjs https://101.37.80.51 --attempts 15
```

判定：退出码 0 且四项全 PASS 才算部署成功。逐条对应：

- **A** 注册连打 15 次：前 5 次 400/403，第 6 次起 **429**（`X-RateLimit-Limit=5`），
  且全程无 201 —— 限流真的在跑（探测 body 恒为 `{}`，**不会建号**）；
- **B** `http://` 同端口连不上 / 80 端口不可达；`https://` 通且证书链受信任
  （自签证书会给 WARN，生产用 certbot 应为 PASS）；
- **C** 不带令牌的 WS 发帧被 `ERROR/AUTH_REQUIRED` + close **4401**；无效令牌同样 4401；
- **D** `/healthz` 返回 200 且 `ok:true`。

WARN 需人工复核（如证书不受信任、80 端口有明文入口）；**任何 FAIL 都不得收口 8080**。

## 7. 回滚预案

| 场景 | 动作 |
|------|------|
| 新容器起不来 / 健康检查不过 | `docker compose logs --tail=100 signaling` 定位；TLS 相关按第 1 步核对挂载；仍不行按下一条 |
| 需要整体回滚 | `docker compose down`；`git checkout <8cc68c7 的父提交 d1419ee>`；`docker compose build && docker compose up -d`；镜像标签 `:rollback-20261021` 可直接 `docker tag` 复用 |
| 客户端大面积连不上（灰度事故） | 服务端 `WS_TOKEN_TRANSPORT` 退回 `both`（老行为全收），再排查客户端版本 |
| 证书事故 | `TLS_KEY_PATH/TLS_CERT_PATH` 置空 → **注意**：只配其一会启动失败，必须**两个都置空**才回到明文；同时安全组临时重开 8080 供旧客户端连通，修复后按第 3→5 步重走 |
| 数据回滚 | `data/` 停服后从 `data.bak-20261021` 恢复 |

回滚后必须重跑第 6 步探测，并在 `doc/安全/` 记一笔事故与原因。

## 8. 残留暴露面（本次不关，登记在案）

1. `/api/auth/login` **无限流** —— 口令暴破面，靠 `INVITE_CODE` + 强口令缓解，后续任务加登录限流；
2. `INVITE_CODE` 默认空 —— 不设时注册对所有 IP 敞口（限流 5 次/10min/IP 只是降速）；
3. 限流桶是**进程内存 + 按 socket 对端 IP**：容器重启即清、多副本各自计数、前置反代不传 XFF 时全客户端共享一个桶（误伤非绕过）；代码不信任 `X-Forwarded-For`，暂无伪造绕过；
4. frame 模式握手放行 + `WS_AUTH_TIMEOUT_MS`（5s）兜底 —— 未鉴权连接可占 socket 至多 5s；
5. `/healthz` 与 `/` 免鉴权，healthz 吐在线数/会话数（侦察信息）；
6. CORS 为 `Access-Control-Allow-Origin: *`（令牌不走 cookie，无 CSRF 放大，但过宽）；
7. 无 HSTS、应用层无 http→https 跳转 —— 靠「只发布 443 + 安全组收口」兜。
